# Aurora Proxy 1.1.14

一个面向 Windows 7 的原生 mihomo 桌面客户端。深色 / 浅色主题、圆角卡片与输入框、简洁导航，使用 .NET Framework WinForms，不依赖浏览器组件。配色以深蓝与石墨灰为底，使用钴蓝主按钮、青绿状态、紫色指标及琥珀色操作提示。

## 开始使用

在 [Releases](https://github.com/IOIgf/Aurora-Proxy/releases/latest) 下载 `AuroraProxy-Win7-x64-v版本号.zip`；不要把 GitHub 自动生成的 Source code 压缩包当成安装包。

1. 将 ZIP **完整解压**到任意目录，例如 `D:\Apps\AuroraProxy`，不要直接在压缩包里启动。
2. 双击 `AuroraProxy.exe`。客户端需要 .NET Framework 4.0 或以上；**Windows 7 SP1 推荐安装 .NET Framework 4.8**。
3. 打开 **订阅 → 添加订阅**，填写 **Clash / mihomo 格式**的订阅链接。名称留空会自动识别，也可以填写自己的名称；本地文件可以选择 **导入 YAML**。
4. 选中订阅，点击 **应用选中**。第一份订阅会自动成为当前配置。
5. 打开 **概览 → 连接代理**，一次操作启动内核并开启系统代理；只需局域网共享 / 手动配置应用时，使用 **仅启动内核**。
6. 在 **节点** 页面选择策略组，双击节点或点击 **使用选中节点**。
7. 使用全局模式前，在 **GLOBAL** 分类中选择代理节点或策略组；若仍选中 DIRECT / REJECT，客户端会保留原模式并引导选择出口。GLOBAL 选择策略组时，还需在该组内选择可用节点。选好出口后会继续刚才的模式切换 / 连接操作，不必再回概览重复点击。

默认代理端口为 `127.0.0.1:7890`，同时提供 HTTP 和 SOCKS5。控制接口为 `127.0.0.1:19090`，每次启动客户端生成随机 API 密钥。

## 常用交互

- **断开代理**恢复系统代理并保留内核，局域网共享可以继续使用；停止内核请使用概览中的 **停止内核** 或托盘菜单。
- 新建订阅可自动预填剪贴板中的 HTTP / HTTPS 链接，需点击导入后才下载；也可直接把一个 `.yaml` / `.yml` 文件拖进窗口。
- 切页保留节点分类、搜索、选中项和滚动位置；订阅刷新和切页保留列表位置。重复点击当前导航不会重建页面。
- 后台处理时可以切页查看，日志仍可滚动、复制与导出；修改操作暂时禁用。常规错误显示在底部，鼠标悬停查看说明，点击错误提示查看日志。
- `Ctrl+F` 打开节点搜索，`Esc` 清空搜索，`Ctrl+R` 刷新节点 / 连接，`Ctrl+L` 打开日志。

## 已实现的功能

- 多订阅添加、编辑、删除、选择、单个更新、全部更新。
- 自动订阅名称：优先读取 `profile-title`（支持 Base64 UTF-8），其次读取 `Content-Disposition` 文件名（支持 `filename*` 中文编码），都没有时使用订阅域名。手动名称优先；自动名称随订阅更新，服务商暂未提供名称时保留上次识别结果。已有订阅可在“编辑”中清空名称后保存来开启自动识别。
- 本地 YAML 配置导入；可以用记事本打开并编辑缓存配置，编辑后重新应用。
- 更新前验证格式；有内核时执行 mihomo `-t` 校验。更新失败保留原配置，活动订阅更新后热重载。
- `subscription-userinfo` 流量与到期信息显示；服务商未提供时显示提示。
- 定时更新：客户端运行期间每 30 分钟检查一次，达到设置的更新间隔后直连更新。
- 手动导入和更新时可选通过正在运行的本地代理下载。
- 内核启动、停止、版本检查、自定义内核路径、端口占用检测。
- 规则 / 全局 / 直连模式，策略组与节点切换，单节点与整组延迟测试，节点搜索。节点页可选择延迟升序 / 降序 / 订阅原顺序，或点击“延迟”列标题切换；未测试和超时始终排在最后。
- 使用选中节点或双击切换后保留节点列表位置与选中项；节点分类下拉框不会因滚轮误操作切换分类。
- 局域网 HTTP / SOCKS5 共享、用户名与密码验证、密码生成、网卡地址选择及代理地址复制。
- 活跃连接管理：来源设备、目标、协议、规则与流量，每 2 秒刷新；支持断开选中或全部连接。
- 当前用户登录 Windows 后在托盘启动客户端，可在设置里开启，默认关闭。
- 下载 / 上传速率、活跃连接数量，内核日志、日志导出。
- 系统代理开关；正常停止、退出或内核退出时尝试恢复原设置。
- Windows Job Object 联动退出；客户端异常退出后，下次打开会根据恢复记录恢复系统代理。
- 托盘运行、关闭 / 最小化收进托盘、单实例、防止同时修改配置。
- 深浅主题、DPI 适配、窗口缩放。
- 按钮悬停和按下的短时过渡、导航选中动效、180 ms 页面滑入、操作中的进度指示；可以在设置里关闭动画，静止控件不持续运行动画计时器。

本次界面修订内容见 `CHANGELOG.md`。升级时退出旧版再解压新版；已有订阅和设置保存在同一个数据目录，会继续使用。

## 标签自动构建与发布

提交代码后，推送 `v主版本.次版本.修订版本` 标签即可自动编译、检查并发布，例如：

```bash
git tag -a v1.1.12 -m "Aurora Proxy v1.1.12"
git push origin v1.1.12
```

- GitHub Actions 在 Windows Server 2022 上使用 C# 4 和固定的 Microsoft .NET Framework 4.0 参考程序集编译，校验内核文件，并运行勾选框缓冲区回归及真实 mihomo 接口检查。
- 标签版本会同步写入生成程序的程序集、界面底部和 ZIP 名称；源码仓库本身不会被构建流程改写。
- 检查通过后，Release 自动附带包含内核的 ZIP 和同名 `.sha256` 文件。`v1.2.0-beta.1` 等带后缀的标签发布为预发行版。
- 推送 `main` 或手动运行 Actions 也会构建，可在对应运行的 Artifacts 下载构建产物；只有版本标签会发布 Release。
- 发布使用 GitHub 自动提供的 `GITHUB_TOKEN`，无需保存个人访问令牌。同一标签重复运行不会覆盖已完整发布的资产。
- 工作流与脚本：`.github/workflows/release.yml`、`ci/build-release.ps1`、`ci/publish-release.ps1`。这两个 PowerShell 脚本用于构建环境，Win7 用户运行程序不需要 PowerShell 7。

## 局域网连接

1. 在“概览”停止内核，打开“局域网”页面，勾选“允许局域网设备使用 HTTP / SOCKS5”。
2. 默认要求用户名和密码。可以生成新密码，也可以设置自己的密码，然后点击“保存共享设置”。
3. 回到“概览”启动内核。局域网共享不依赖本机系统代理开关。
4. 在“局域网”选择实际连接路由器的网卡，把显示的 **IP 和端口**填入同一 Wi-Fi / 路由器上的设备。HTTP 和 SOCKS5 共用该端口，远端不要填写 127.0.0.1。
5. 启用验证时，其他设备还需填写共享用户名和密码。若设备没有验证输入入口，使用支持验证的代理客户端；也可以在受信任的局域网自行关闭验证。
6. 若无法连接，点击“防火墙设置”，允许 `core\mihomo.exe` 通过家庭 / 工作网络，并检查路由器的设备隔离功能。程序不会自动修改防火墙。

共享入口只允许 10/8、172.16/12、192.168/16 和 169.254/16 的 IPv4 私网来源。本机 127/8 与 ::1 可跳过认证；API 控制接口固定在 127.0.0.1。电脑与内核需一直运行；使用完毕后，在远端设备关闭代理。

“连接说明”可查看并复制连接步骤，说明文本不会包含共享密码。开机启动仅启动托盘客户端，仍需手动启动内核。

## 内核与 Win7

此包附带官方 **mihomo v1.19.32 / windows-amd64-v1-go120** 内核，适用于 **64 位 Windows**。客户端 EXE 为 AnyCPU。

**32 位 Win7**：从官方发布页下载 `windows-386` 内核，解压后替换 `core\mihomo.exe`，或在设置中选择替换后的文件。不要将压缩包重命名为 EXE。

- 官方内核发布页：https://github.com/MetaCubeX/mihomo/releases
- 官方系统兼容说明：https://wiki.metacubex.one/en/startup/faq/
- .NET Framework 4.8：https://dotnet.microsoft.com/en-us/download/dotnet-framework/net48

这份客户端以 .NET Framework 4.0 API / C# 4 为兼容基线。已完成跨平台编译与真实 Linux mihomo 内核接口测试，**尚未在真实 Windows 7 上完成运行验收**；WinINet 系统代理设置、托盘、Windows Job Object、Win7 TLS / DPI 行为仍需在实际机器确认。

## 支持的订阅格式与配置行为

- 支持 UTF-8、单文档、顶层块式映射的 Clash / mihomo YAML。支持节点列表、代理集合和完整配置。
- **不支持**原始 `ss://`、`vmess://` 节点链接、Base64 节点订阅、根级流式 YAML、根级合并键或多文档 YAML。请向服务商索取 Clash / mihomo 订阅。
- 程序保留订阅中的节点、策略组、规则和 DNS 等内容；为确保端口与控制接口一致，运行配置覆盖代理入口、API、模式、TUN、listeners、局域网范围和入口认证相关字段。
- 本版采用系统代理，TUN 固定关闭。系统代理适用于遵循 Windows 代理设置的应用；游戏等软件可能需要自行设置 SOCKS5 或 HTTP 代理。
- 只有节点列表而无策略组时，程序补充 `AURORA` 选择组和默认匹配规则。含自定义策略组但没有 `rules` 的配置，规则模式默认直连，可切换全局模式或自行补充规则。
- 本地配置的相对路径以数据目录的 `runtime` 文件夹为基础。若配置引用本地规则集 / GEO 文件，请将这些依赖放入该文件夹。内核可能按配置自行下载所需数据。
- 延迟测试使用 `https://www.gstatic.com/generate_204`；测试结果取决于该网址的可达性。

## 数据与恢复

配置存储在 `%LOCALAPPDATA%\AuroraProxy`，不会写入软件目录。设置页面可直接打开该目录。

- `settings.json`：界面设置和订阅元数据。Windows 下订阅链接与局域网共享密码使用当前账户的 DPAPI 加密。
- `profiles`：缓存的原始 YAML。
- `runtime`：实际运行配置、内核数据和缓存。
- `proxy-recovery.json`：开启系统代理前的备份。恢复时，如果代理已被其他软件或用户修改，客户端会保留外部修改。

YAML 需要供内核读取，节点凭据和运行配置中的局域网共享凭据仍是本地明文。复制软件目录不会携带个人订阅；备份个人配置请复制数据目录。DPAPI 加密的链接和共享密码不可直接迁移到另一个 Windows 账户。

恢复记录保留到成功恢复。系统代理的恢复依赖正常退出流程：客户端被任务管理器强制结束或系统异常断电时，WinINET 设置可能暂时停留在代理地址上；下次打开客户端会读取 `proxy-recovery.json` 自愈兜底，重新接管并按备份恢复原设置（Job Object 也会联动清理残留内核进程）。若来不及重启客户端且网络不通，可在 Windows **Internet 选项 → 连接 → 局域网设置**中手动清除代理服务器并还原原 PAC / 自动检测设置。

## 常见问题

**软件无法启动 / 缺少运行库**：安装 .NET Framework。Win7 建议先升级到 SP1，再安装 4.8。

**订阅下载失败**：检查链接、过期时间和网络。Win7 需具备 TLS 1.2 支持、有效证书及相应系统 / .NET 更新；不要关闭证书校验。内核运行后可尝试勾选“通过代理下载”，或先在浏览器下载 YAML 后导入。

**不是有效的 Win32 应用程序**：核对操作系统与内核位数；32 位系统必须使用 `windows-386`。

**内核检查失败 / GEO 文件缺失**：查看日志，并检查订阅引用的规则或数据文件是否能下载。配置验证失败时系统代理不会被开启。

**端口被占用**：先停止其他代理软件，或在设置中修改两个端口；本地端口和控制端口不能相同。

**点关闭后仍在运行**：默认收进托盘。右键托盘图标选择“退出”，或在设置中关闭该行为。

## 源码与构建

客户端源码位于 `src`，使用 C# 4，不需要 NuGet 依赖。在安装了 .NET Framework 4.x 的 Windows 上双击 `build.cmd` 即可重新编译。构建脚本使用系统的 `v4.0.30319\csc.exe`。

测试位于 `tests/IntegrationTests.cs`，覆盖实际内核启动、校验、重载、模式切换、中文节点和订阅下载。测试需要对应平台的 mihomo 内核。详细验收结果见 `TESTING.md`。
